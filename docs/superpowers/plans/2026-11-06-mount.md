# Mount — Rencana Kerja

> **Untuk agen:** kerjakan per bagian (A–D). Berhenti di akhir tiap bagian untuk cek manual oleh pemilik (pemilik yang menguji di browser; agen cukup `npm test`, `npm run build`, lalu jalankan server lokal dan beri alamatnya). Commit setelah pemilik oke. Centang langkah yang selesai. Sebelum menyentuh file, lihat `git status`: file yang sedang diubah sesi lain (mis. `render3d/actors.js`) jangan ikut di-commit kecuali bagianmu sendiri.

**Tujuan:** pemain bisa memanggil mount di wilayah terbuka, melaju 1,6–2,0× lebih cepat, dan (yang Legendaris ke atas) terbang menyeberang air. Ada 9 mount yang dikoleksi dari hadiah cerita, Kandang, Lencana, dan bos. Tiap mount memberi satu bonus kecil.

**Arsitektur:**
- `data/mounts.js`: semua angka.
- `run/mount.js`: logika naik/turun murni. Keadaan disimpan di objek `Game` (`run.mount`), dipanggil dari `Game.step`, `stepPlayer`, dan `hurtPlayer`.
- `run/fieldmap.js`: `pushOut` dapat opsi `fly`.
- `meta/stable.js`: koleksi, pembelian, bonus, hadiah cerita, dan jatuhan bos dengan jaminan.
- Gambar memakai `art/mounts.js` yang sudah ada (`drawMajesticRidden`, `drawMajesty`, `drawSummonRing`).

**Tech:** Vite 7, JS murni, Vitest, Three.js (render3d) + canvas 2D.

**Spesifikasi:** `docs/superpowers/specs/2026-10-26-critter-quest-arcade-design.md` §35 (35.1 cara main, 35.2 koleksi, 35.3 tampilan, 35.4 teknis).

## Aturan global
- Semua angka di `app/src/data/`, bukan di logika.
- `run/` dan `meta/` murni tanpa DOM, wajib tes Vitest di samping modul.
- Simulasi memakai `rand()` dari `core/rng.js`. Efek gambar (debu, partikel) memakai RNG efek sendiri, bukan RNG simulasi. `meta/` menerima `rng` sebagai argumen.
- Struktur save berubah di Bagian C: `SAVE_VERSION` 20 → 21 + langkah `migrate()` 20 + tes.
- Teks baru dibungkus `tr()`/`t()` dan kamus EN di `src/i18n/` (Bagian D melengkapi).
- Hot loop tanpa alokasi baru per frame.
- Commit tanpa baris `Co-Authored-By`. Jangan push.
- **Perubahan terhadap spesifikasi:** tombol PC untuk mount adalah **R** (Ride), bukan M. M sudah dipakai untuk peta (`main.js` `onAction`). Perbarui §35.1 dan §35.4 di Bagian A.

```js
// Mount state for a region run (spec §35.1). Pure: the caller (run/run.js) asks it to start a
// summon, steps it, and knocks the rider off on actions / hits / leaving the open world.
import { MOUNT } from '../data/mounts.js';

// def: { id, rarity, fly, skin } of the active mount, or null when the character has none
export function freshMount(def = null) {
  return { id: def?.id ?? null, rarity: def?.rarity ?? 0, fly: !!def?.fly, skin: def?.skin ?? 0, state: 'none', t: 0, lock: 0 };
}
export const isRiding = (m) => m.state === 'riding';

export function startSummon(m) {
  if (!m.id || m.state !== 'none' || m.lock > 0) return false;
  m.state = 'summoning'; m.t = 0;
  return true;
}

// → 'rode' on the step the summon finishes, else null
export function stepMount(m, dt) {
  if (m.lock > 0) m.lock = Math.max(0, m.lock - dt);
  if (m.state !== 'summoning') return null;
  m.t += dt;
  if (m.t < MOUNT.summon) return null;
  m.state = 'riding'; m.t = 0;
  return 'rode';
}

// reason: 'action' (attack / skill / dodge: no lock), 'hit' (knocked off: locked), 'leave'
export function dismount(m, reason) {
  if (m.state === 'none') return false;
  m.state = 'none'; m.t = 0;
  if (reason === 'hit') m.lock = MOUNT.fallLock;
  return true;
}

export const mountSpeedMul = (m) => (m.state === 'riding' ? MOUNT.speed[m.rarity] : 1);
export const canCrossWater = (m) => m.state === 'riding' && m.fly;

// an action that knocks the rider off; attackWanted: the attack would really fire this step
export const wantsAction = (intent, attackWanted) => attackWanted || intent.dodge || intent.skill1 || intent.skill2 || intent.skill3 || intent.skill4 || intent.ult;
```
